# 本地数据备份与校验恢复 V1

在现有 Scheduler 与审计归档上提供用户显式操作的整组备份。Core 定义维护接口与恢复规则，本地适配器负责文件、租约、校验与激活；桌面只展示预览并收集确认。没有新增模型、工具、远程入口、系统启动配置或后台服务。本轮没有读取或迁移真实用户数据，也没有 commit / push / PR。

## 桌面操作

“任务 → 数据备份与恢复”默认折叠。

1. 手动停止调度宿主，再点击“释放存储”。运行中或暂停中的宿主不能释放。释放后聊天和旧审批按钮暂停使用，避免旧连接继续操作数据。
2. 点击“创建整组备份”，或刷新已有备份列表。创建不改变任务、批准、记忆与计划，也不触发任何工具。
3. 选择一份备份，点击“校验并预览恢复”。预览包括将恢复的数据数量、需要核对的任务、失效的批准与取消的计划。
4. 核对数据替换、旧记忆可能重现、实际文件不回滚以及旧执行已停止等说明，勾选确认，再点击“确认恢复所选快照”。
5. 恢复成功后仍保持断开。点击“重新连接”读取新数据，先核对未完成任务；调度宿主保持停止，旧计划需要重新显式创建。

主库损坏导致普通连接无法打开时，备份面板仍可以独立列出、校验并恢复已有备份。另一个进程占有写入租约时，维护操作拒绝执行。操作失败不会自动重试、删除原数据或自动选择未激活的副本，需处理问题并重新预览。

## 备份内容与保留

整组快照包含主库原字节以及主库清单引用的全部 `audit-archives` 冷文件。主库包含任务/执行/审批、长期 Memory、用户选择保存的对话、计划、触发记录、归档清单、退役 ID、调度水位与单调序号。孤立归档、临时文件、writer.lock、实际生成的 `agent-files`、桌宠设置和环境变量不复制。

**备份包含个人数据，采用独立保留规则。** 忘记记忆、清除对话以及 30 天对话保留只作用于活动库，不擦除备份与保留的旧数据。恢复旧快照可以重新带回后来删除的记忆，必须由用户核对并明确确认；原对话保留规则在重开后继续执行。首版不自动生成、轮换、过期或删除备份，不提供隐私擦除或备份删除按钮。用户需另外管理全部旧副本。

当前实现使用受管理的本机目录，不是 ZIP。只接受合法备份 GUID，不接受任意条目路径；可另行复制**整个 GUID 目录**到独立介质保存。恢复入口只读取本机 `backups` 下的整组目录，首版没有跨盘导入/导出向导。保留在同一磁盘的快照无法应对磁盘丢失。

每份 `manifest.json` 为格式 1：ID、UTC 创建时间、源 schema、记录数量、合计字节数，以及每个文件的名称、字节长度和 SHA-256。创建与恢复均检查全部文件的结构、内部引用和校验和。列表只校验清单，不代表文件已通过完整验证；必须点击恢复预览。非法路径、缺失文件、未知版本、超限或可疑凭证均拒绝使用。

最多 8 份已发布备份；主库及每个冷文件各不超过 8 MiB，清单不超过 64 KiB，每份最多 65 个文件。最多保留 16 个恢复 generation 目录，未完成的准备目录也占名额。达到上限后拒绝新操作，保留已有数据；首版没有自动清理。校验和发现意外损坏，不提供抵御恶意重写所有校验和的认证。

取消的计划仍占用既有 32 个计划名额；达到计划上限时不能直接新建，不会为了恢复而静默丢弃调度审计。

凭证过滤检查原始 JSON，包括未识别字段与常见嵌入 JSON 文本；沿用原记忆/参数校验，并拒绝 API Key、Token、密码、认证、私钥等常见形式。不读取环境中的真实 Key。过滤是保守规则，可能误拒绝文本，无法完整识别所有个人敏感数据，不是加密或 DLP 系统。

## 数据布局与迁移

逻辑根仍为 `%LOCALAPPDATA%\TamagoPet\agent-v2\tasks`，单写入者锁始终位于该根目录。主文档保持 schema **5**；备份清单和活动选择文件分别为格式 **1**。

```text
tasks/
  writer.lock
  tasks.v2.json                  # 初始活动库；首次恢复后保留为原库
  audit-archives/                 # 与初始主库配对的原归档
  backups/<backup GUID>/
    manifest.json
    tasks.v2.json
    audit-archives/<archive GUID>.json
  active-store.json              # 只有明确恢复才创建/原子替换
  generations/<restore GUID>/
    tasks.v2.json                # 完整校验并撤销旧执行授权后的活动库
    audit-archives/
    restore-manifest.json
    previous-selector.json       # 若有旧选择文件，保存其原字节
```

没有选择文件时沿用原路径；有合法选择文件时，只打开其固定 GUID generation，归档在所选主库同级。所选主库缺失或选择文件损坏时拒绝普通开库，不回退到原库或建立空的新库。逻辑 `StorageIdentity` 保持不变，文件工具目标目录也保持不变。重新备份读取所选 generation，不读取已经保留的旧根数据。

合法 schema 2/3/4 可原样备份，在经过确认的新 generation 中升级为 5，补齐空集合与单调序号；源文件不迁移、不覆盖，也不从任务生成用户事实。原 schema 5 的 Memory、对话、任务/归档身份及调度防重记录保留。

**首次恢复后应只使用支持 `active-store.json` 的此版本。** 较旧 EXE 不理解新布局，可能读取保留在根目录的旧主库和旧批准；不能将其用于已恢复的数据目录，也不能手工删除选择文件来“降级”。此版本不对任意旧二进制提供降级保护或兼容保证。Schema 5 自身也不受更早的 V2/V3 EXE 支持。

## 审批与执行安全

恢复预览绑定目标逻辑根、当前选择文件/主库/引用归档的内容哈希、完整源快照和本次预览 ID/时间。明确用户确认对象只能用于同一预览；源备份或目标数据变化后必须重新预览。确认不是模型工具，也不接受从模型输出构造的审批请求。

恢复不会延续旧执行授权：

- 所有 Pending / Approved 批准标为 Superseded，并清除规范化参数。旧 Tool + 参数绑定不能执行。
- 未结束任务保守隔离：Dispatching 转 Unknown；含 Unknown 执行进入 NeedsReview，其他未完成任务进入 Interrupted。
- 尚未派发的 Ready / WaitingForPermission 执行关闭，不调用工具。结果明确的已结束记录保留。
- 所有未取消计划都永久取消并关闭，不能通过“恢复计划”重新启用。相关未完成 trigger 进入 NeedsReview；重新显式创建计划后，每次运行仍走原 Runtime / Executor / Permission。
- 人工核对复用现有 reconciliation，只记录实际结果，不重放工具。核对完成后可以正常创建新请求、批准新操作并归档。

实际文件及备份之后发生的操作不会回滚。快照不是全部外部副作用的历史：后来产生的任务、状态和实际效果可能不在旧快照中。恢复前应停止旧宿主/执行并人工核对，不能把没有出现在快照里的操作当作从未执行过。当前版本没有通用副作用补偿或跨进程 fencing。

## 原子激活与崩溃窗口

恢复不是逐个覆盖当前文件的跨文件事务。持有同一根租约后，在 `generations/.pending-<预览 GUID>` 写入完整隔离数据，逐文件 `Flush(true)` 并校验，保存恢复清单，原子 rename 为最终 generation。重新确认目标未变后，只对一个 `active-store.json` 临时文件执行 `MoveFileEx(REPLACE_EXISTING | WRITE_THROUGH)`。原主库、原归档、上一代数据以及原快照均保留。

| 中断窗口 | 重开结果 |
| --- | --- |
| 写入或校验准备数据失败 | 原选择/数据不变；部分目录不参与恢复 |
| 整组准备完成，选择文件尚未提交 | 原数据继续有效；不会自动提升已准备 generation |
| 选择文件提交后，界面尚未收到结果 | 打开完整新数据；旧批准已失效，无工具重放 |
| 所选数据损坏或缺失 | 拒绝普通开库；独立校验其他快照并重新确认恢复 |

同一成功激活的确认可以幂等重试，返回原恢复收据；后续合法写入不会被这次重试覆盖。若尚未激活，只接受重新校验后与本次预览完全一致的准备数据。

数据比较和预览绑定对 JSON 对象键做 ordinal 规范化，保留数组顺序；避免 .NET Framework 反射缓存导致 DTO 字段顺序改变而误报损坏。文件长度与 SHA-256 始终检查原始字节。时间使用既有序列化器的秒精度。进程崩溃测试不代表任意文件系统、磁盘硬件故障或突然断电下的绝对持久性保证。
