# 用户可控的审计归档 V1

本阶段在 Scheduler V1 的未提交实现上增量完成，不新增 Agent 工具或模型能力。审计以当前代码、schema 和回归为准；没有提交、推送、创建 PR、读取真实用户库或更改系统启动配置。

当前增加 [整组备份与校验恢复 V1](data-backup-v1.md)：逻辑根不变，明确恢复后由 `active-store.json` 选择新的完整主库/归档目录。归档始终跟随所选主库，不会自动恢复执行。字段安全比较已采用 JSON 键规范化，避免 Framework 反射缓存引起属性顺序变化而误报损坏；文件原始字节的 SHA-256 校验保持不变。下面保留归档阶段的测试基线。

## 操作路径与边界

“任务 → 历史记录归档”默认折叠。先手动停止调度宿主，预览可归档数量及活动用量，再明确点击“确认归档”。记录变化后旧预览失效，必须重新预览；空预览不能提交。宿主启动与整段归档提交互斥，暂停分发不能代替停止；归档不会暗中停止或重启宿主。

可归档：Succeeded / Failed / Cancelled / Blocked，且全部执行与审批已经关闭。排除 Created / Queued / Running / WaitingForApproval / Interrupted / NeedsReview，以及 Ready / WaitingForPermission / Dispatching / Unknown 执行或 Pending / Approved 审批。已结束的调度任务只有在对应 trigger 的最终检查点完成后才移走，两者在同一主库提交中一起移走。Missed 记录可以独立归档。人工 reconciliation 已明确记录的结果可归档，但不再次调用工具。

归档可在同一面板查看经过校验的只读摘要；界面最多展示 12 个任务及 8 条调度记录，并显示其余数量。此版本不提供导入、恢复执行、删除归档、自动归档或自动清理。任务和审批的状态机没有改变，UI 仅提交预览/确认/读取动作。

## 数据与迁移

主库路径继续为 `%LOCALAPPDATA%\TamagoPet\agent-v2\tasks\tasks.v2.json`。schema **5** 新增 `Archives` 清单和独立 `TriggerSequence` 计数。合法 schema 2/3/4 通过原子完整文档提交升级；旧任务、批准、Memory、对话、计划及触发保持身份和现有语义，初始计数来自既有最大触发序号，不生成新计划或事实。旧 EXE 无法读取 schema 5；降级需要事先保留的旧库备份。已有对话保留规则继续适用。

归档文件固定在主库同级 `audit-archives/<归档 GUID>.json`，自有格式版本 1，不接受任意文件路径。清单记录文件长度、SHA-256、预览绑定、已归档 Task/Trigger ID、最大序号和各计划的当地时间水位。最大 64 份归档，每份及主库各不超过 8 MiB；活动库仍限制 256 个任务、512 条触发和 32 个计划。归档不会释放计划名额。

保存的任务元数据包含任务身份、时间、状态、执行/审批状态、参数摘要哈希和枚举结果。不复制规范化参数、输入/输出正文、原始异常或人工备注；旧库中可疑标识会变为哈希别名。调度归档只留发生时间、范围/次数、状态、预算与请求哈希，不复制 `RequestJson`。Memory、对话、计划正文和实际生成的文件保持独立，不参与归档或模型上下文检索。内容过滤沿用现有保守规则，不是完整的 Secret 识别系统。

预览绑定本机存储身份、归档 ID/创建时间、当前清单/序号以及每个候选记录的完整版本和内容哈希。采用现有序列化器支持的秒级时间精度，以保证重开和校验一致。确认只接受同一份候选记录；重复确认已提交的相同预览返回原清单，不产生新文件。

## 安全提交与恢复

两个文件的写入不宣称是一个跨文件事务。顺序如下：

1. 持有原存储 gate 和单写入者租约，重新检查预览、容量和候选记录。
2. 写冷文件临时副本，`Flush(true)` 后原子 rename；不覆盖已存在文件，重试只接受长度、校验和、结构完全一致的副本。
3. 校验最终冷文件，持有禁止写入/删除的文件句柄，再用原主库原子替换同时安装清单及移除候选记录。
4. 只有主库提交完成才返回归档结果。UI 刷新活动任务、调度记录和只读归档。

| 中断窗口 | 重启后语义 |
| --- | --- |
| 冷文件写入/校验失败 | 原活动记录未移除，实例拒绝继续写入，重开核对 |
| 冷文件完成，主库尚未提交 | 可能留下孤立冷文件，忽略它；原活动记录仍在，不自动提升或重放 |
| 主库已经提交，界面尚未收到结果 | 清单指向已校验归档，活动记录已移走；同一预览重试幂等 |
| 已提交归档损坏/丢失 | 开库失败并保留原主库，不抹掉清单或伪装为空历史 |

开库逐份验证已提交文件的长度、校验和和结构。未提交 `.tmp` 与没有清单的冷文件永远不参与任务恢复。读文件时锁定文件并限制分配长度。I/O 提交失败后沿用适配器 fail-closed 行为，必须退出并重新打开。

退役 Task/Trigger ID 不能作为新的活动记录保存；计划游标不能倒退至已归档水位。全局触发序号跨归档单调增长，清空 512 条活动触发后下一条仍为 513。时钟回拨、轮询和进程重启不会重建旧 occurrence。归档数据只能经只读端口获取，不会加入 Runtime 的任务列表或复活旧批准。恢复未知副作用的原有人工核对流程仍保留在活动库。

备份和恢复必须把主库及其 `audit-archives` 目录作为一组保留。校验和用于发现意外损坏，不提供抵御恶意修改的认证；单写入者、本地 Windows 文件系统、无磁盘硬截止等原有限制不变。孤立文件不会自动删除，需要后续提供可验证的管理流程。达到 64 份清单或主库容量上限时仍安全拒绝继续归档，不静默删除审计。
